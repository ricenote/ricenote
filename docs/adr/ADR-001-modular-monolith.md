# ADR-001：v1 采用模块化单体，而非微服务

- 状态：已接受
- 日期：2026-10-11

## 背景

RiceNote 面向个人写作者与小型站点，部署目标是一位作者用一台 VPS 就能长期维护的博客系统。
规划说明书将"个人 VPS 易部署"列为核心产品目标之一。

## 决策

v1 采用**模块化单体（Modular Monolith）**：

- 单一 Node.js 进程承载全部业务，插件在**同一进程内**以模块形式加载；
- 模块边界靠契约（Service Registry / Event Bus / Slot）而非网络调用维持；
- 不引入服务发现、消息队列、RPC 等分布式基础设施。

## 理由

- 单进程部署极大降低运维成本：无需容器编排、服务注册中心、链路追踪；
- 个人站点规模下，网络与序列化开销远大于模块内调用；
- 插件生态初期需要"低门槛"——作者只需写一个目录加 manifest，而不是部署一个微服务；
- MySQL 的强一致事务在单进程内可直接使用，无需分布式事务。

## 后果

**正面**

- 部署、备份、恢复都可以按"一个目录 + 一个数据库"处理；
- 插件启停是进程内的状态变更，调试成本低；
- 事件总线可用简单实现起步。

**负面 / 约束**

- 插件无进程隔离，**不存在真正的安全沙箱**：仅允许受信任管理员安装（见 ADR-005）；
- 单进程故障域覆盖全部插件，因此必须实现插件错误边界与"核心可独立启动"的恢复模式；
- 后续若需横向扩展，需要引入进程外缓存与事件 Outbox（已预留接口）。

## 替代方案

| 方案 | 否决原因 |
| --- | --- |
| 微服务 + 独立插件进程 | 与"个人 VPS 易部署"目标直接冲突；运维成本过高 |
| 独立插件进程 + IPC | 需要自定义协议与生命周期管理，复杂度远超 v1 收益 |
| 纯库式（无进程，编译期组合） | 无法满足"运行期启用/禁用插件"的验收标准 |
