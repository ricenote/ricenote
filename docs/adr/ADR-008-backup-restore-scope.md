# ADR-008：备份覆盖「数据库 + 上传文件 + 插件/主题清单」，恢复前必须自动快照

- 状态：已接受
- 日期：2026-10-11

## 背景

说明书第 10 章要求："备份：数据库 + storage + 已安装插件与主题清单，定期做恢复演练。"
同时第 9 章要求后台「系统」分区提供"基础设置、日志、备份、恢复"。

备份的价值取决于"能不能恢复回去"，因此**恢复路径的可靠性**比备份的完整性更关键：
一次恢复会覆盖现有数据，若恢复结果不符预期而无法回退，就是一次数据事故。

## 决策

1. **备份范围**（一个 ZIP 三个部分）：
   - `manifest.json`：导出时间、应用版本、站点标识、数据库信息、插件/主题清单、uploads 统计；
   - `database.sql`：`mysqldump` 全量导出；
   - `uploads/**`：媒体库文件。
2. **流式导出**：`mysqldump` 的 stdout 直接进入归档流并作为 HTTP 响应体返回，
   内存占用与数据量无关；不落地大文件。
3. **凭据不入命令行**：数据库密码经临时 `--defaults-extra-file`（0600 权限）传递，
   用后立即删除，避免出现在 `ps` 输出与结构化日志中。
4. **恢复前自动快照**：任何恢复动作（上传包恢复、从历史快照回滚）都会**先**把当前状态
   导出为 `storage/backups/backup-<时间戳>.zip`。恢复失败或结果不符预期时可回滚。
5. **恢复顺序**：安全解压 → 校验清单 → **生成当前状态快照** → 导入数据库 → 覆盖上传目录。
   上传目录在数据库导入成功后才替换，尽量缩小"半完成"窗口。
6. **恢复后需重启**：数据库被替换后，进程内的插件状态、主题设置缓存均已过期，
   因此响应中返回 `restartRequired: true`，并清空 HTML 缓存。
7. **工具缺失可诊断**：`mysqldump` / `mysql` 不在 PATH 时返回结构化
   `RN_BACKUP_TOOL_MISSING`（503）与安装提示，而不是 500 或"下载到一半的损坏 ZIP"。
   工具路径可通过 `MYSQLDUMP_BIN` / `MYSQL_BIN` 显式配置（Windows 官方安装包默认不入 PATH）。
8. **保护点文件**：上传目录中的点文件（`.gitkeep`、`.DS_Store`）不进入备份，
   否则它们没有扩展名、会被恢复端的白名单拒绝，导致"自己导出的备份无法恢复"。

## 理由

- 三部分缺一不可：只有数据库会丢图片，只有文件会丢内容与插件状态；
- "恢复前快照"把不可逆操作变成可逆操作，成本只是一次导出；
- 拒绝隐式行为：不做定时任务与保留策略（v1 由运维自行 `cron` + 清理快照）。

## 后果

**正面**

- 恢复可回滚，管理员敢于执行演练；
- 备份包自描述（`manifest.json`），恢复前可只读预览"这个包是什么"；
- 与主题/插件安装共享同一套 ZIP 安全校验，恶意备份包在预览阶段即被拒绝。

**负面 / 约束**

- 大站点导出会占用较长时间与磁盘 IO，且恢复期间应避免写入；
- 快照会占用磁盘空间，需要人工清理（后台提供删除入口）；
- 恢复后必须重启进程，属于 ADR-004 同一约束的延伸。
