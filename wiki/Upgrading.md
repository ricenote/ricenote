# 升级已部署实例

插件与程序本体的更新方式**不同**：

- **插件可以自助更新**（后台或 CLI，升级失败自动回滚）。
- **程序本体目前是手动流程**（取新版本 → 装依赖 → 构建 → 校验 → 迁移 → 重启）。

---

## 1. 先备份数据库（不能省）

迁移**只有前向演进**：插件停用不删表，且没有 down 迁移。所以升级前先导出：

- 后台「备份与恢复」可一键导出（数据库 + `storage/uploads` + 插件/主题清单，流式 ZIP）；
- 或自行 `mysqldump`。

> 备份与恢复页面在恢复前会**自动生成当前状态快照**，把不可逆操作变为可回滚 —— 但升级前主动备份仍是最稳的一步。

---

## 2. 更新插件

| 方式 | 操作 |
| --- | --- |
| 后台「扩展中心」 | 「官方插件目录」里可直接安装；已装版本低于推荐版本时提示「可更新」并支持行内更新 |
| CLI | `pnpm plugin updates` 检查更新 · `pnpm plugin update <pluginId>` 按已记录来源更新 · `pnpm plugin jobs` 查看任务历史与日志 |

- 三种来源都支持：npm Registry（可带版本区间）、Git 仓库（tag / 提交 / 分支）、本地目录（含压缩包）。
- **升级失败会自动回滚**，不会让现有版本消失，也不会留下半成品目录。
- 插件声明的**宿主区间跟随次版本**（例：宿主 `0.5.1` 仍对应 `^0.5.0`）——
  **补丁升级不用动区间，次版本跃迁才需要**。请用上面的方式更新插件，不要手改插件的 `package.json`。
- 插件的启停**必须重启进程**才生效（受控重启，ADR-004 / ADR-012）。

细节见 [[插件安装与更新|Plugins/Install-and-Update]]。

---

## 3. 更新程序本体

```bash
# 拉取最新代码（--ff-only：历史分叉时直接失败，不会在服务器上留下半成品合并）
git pull --ff-only

pnpm install  # 可复现安装；若报 OUTDATED_LOCKFILE，说明该提交的 lockfile 未同步
pnpm build
pnpm validate                    # 启动前校验插件与主题清单
pnpm migrate                     # Core 与插件迁移（加锁串行、幂等）
```

然后重启进程（systemd / 进程管理器）。后台也提供一键重启（顶栏「待重启」按钮）。

> 迁移其实会在**启动时自动执行**：Core 迁移由内核完成，已启用插件的迁移由插件管理器完成。
> 显式执行 `pnpm migrate` 的价值是**先把输出看到、失败早暴露** —— 它会按 scope 打印「新增 N 项，跳过 M 项」。

> 回退一般用不上，但真需要时：切回上一个可用提交后要重新 `pnpm install && pnpm build` 再重启，
> 并且注意**迁移不可逆** —— 已前向演进过的库不会因为回退代码而一起回退。

---

## 三条硬注意事项

1. **不要修改已应用的迁移文件**。每个迁移都记录了 SHA-256 校验值，内容被改动会**拒绝启动**；演进只能新增迁移文件。
2. **迁移不可逆**。只有前向演进，第 1 步的备份不能省。
3. **插件与宿主要配套**。`.env` 里的 `RICENOTE_PLUGINS` 声明式清单在启动期**只核对不安装**：
   缺件或版本不符会直接打印可执行的安装命令；也可以重跑 `pnpm run setup`（它以已有 `.env` 为默认值并跳过已装插件）。

## 4. 升级后自检

| 检查 | 期望 |
| --- | --- |
| `GET /api/health` | `version` 是新版本，`plugins.failed` 为 0 |
| 启动日志 | `RiceNote 启动完成 started=N failed=0` |
| 后台「扩展中心」 | 需要的插件齐全，且不再提示「可更新」 |
| 后台「运行日志」 | 无新增 `error` 级别条目 |
| 站点前台 | 首页与一篇内容可正常打开，主题样式与插件功能正常 |

---

## 升级路径速查

| 你的情况 | 要做的事 |
| --- | --- |
| 只更新插件 | 后台扩展中心更新，或 `pnpm plugin update <id>`，然后重启 |
| 只更新程序本体（补丁版本） | `git pull --ff-only` → `pnpm install` → `pnpm build` → `pnpm migrate` → 重启 |
| 程序本体次版本跃迁（如 `0.5.x → 0.6.0`） | 同上，**并且**需要检查/更新插件声明的宿主区间（用插件更新流程，而不是手改） |
| 从很旧的版本跨多个版本升级 | 建议逐里程碑升级并每次自检；先备份，再逐版本执行上面流程 |
| 环境重建 | 保留 `.env`（`RICENOTE_PLUGINS` 即是清单）与 MySQL 数据，重跑 `pnpm run setup -- --from-manifest` |
