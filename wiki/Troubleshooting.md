# 故障排查

排查顺序：**先看日志 → 再看健康检查 → 最后才怀疑代码**。RiceNote 的启动摘要与 `/api/health` 已经覆盖了绝大多数问题的定位入口。

---

## 0. 三个通用定位入口

| 入口 | 能看出什么 |
| --- | --- |
| 启动摘要横幅 | 版本、环境、Node、根目录、数据库（含延迟）、激活主题、插件状态分组、路由/服务/插槽/事件计数、监听与访问地址、启动耗时；**失败 / 排除 / 无效插件单独列出** |
| `GET /api/health` | `status`、`version`、`database.reachable` 与 `latencyMs`、`plugins.{started,failed,invalid}`、`theme`、`cache`、`node`、`restartRequired` |
| 后台「运行日志」 | 按级别 / 时间范围 / 关键字 / 文件过滤 + 分页；每条日志带**请求 ID** 与插件名 |

调试技巧：

- 把 `LOG_LEVEL=debug` 打开可看到更细的启动与解析过程；
- 日志文件始终是 **JSON Lines**，便于 `jq` 过滤；
- 非 TTY（CI / 重定向）时终端自动输出 JSON，颜色关闭。

## 1. 启动失败

| 症状 | 可能原因 | 处理 |
| --- | --- | --- |
| 提示缺少 `.env` 或库结构未建 | 尚未初始化 | 按提示执行 `pnpm run setup`（不是让用户从数据库错误栈里反推） |
| `RN_DB_UNAVAILABLE` / 无法连接数据库 | 连接参数错、MySQL 未启动、容器网络 | 核对 `DB_*` / `DATABASE_URL`；`docker compose ps` 看 mysql 健康状态 |
| 配置校验失败（Ajv） | 环境变量类型或取值非法 | 错误里会指出字段；对照 [[环境变量参考\|Configuration]] 的取值区间 |
| **迁移校验值不匹配 → 拒绝启动** | 已应用的迁移文件被改动过 | 把该文件恢复原样；演进请**新增**迁移文件 |
| 启动日志 `failed=N > 0` | 有插件启动失败 | 见第 3 节 |
| 端口被占用 | 已有实例在跑 | 换 `PORT` 或停止旧进程 |

> 内核在数据库不可用时会进入**恢复模式**：仍提供安装/维护界面与诊断服务，核心不崩溃 —— 因此“页面能打开但什么都做不了”往往是数据库问题。

---

## 2. 迁移问题

| 症状 | 说明与处理 |
| --- | --- |
| `pnpm migrate` 报某个迁移校验值不匹配 | 该迁移文件内容被改过。恢复文件内容，或用备份回滚数据库后重新迁移 |
| 迁移“跳过 M 项” | **正常**：已应用的迁移会跳过，迁移是幂等的 |
| 插件启用了却没建表 | 确认插件确实处于 ENABLED / STARTED 状态（`pnpm plugin`）；插件的迁移随启用执行 |
| 想回退迁移 | **不支持**。只能从备份恢复整库 |

---

## 3. 插件问题

| 症状 | 可能原因 | 处理 |
| --- | --- | --- |
| 插件状态 `FAILED` | 入口文件缺失、依赖未装、启动期抛错 | 看后台「扩展中心」的诊断与日志；`pnpm validate` 做静态校验 |
| 日志提示“缺件”或版本不符 | `RICENOTE_PLUGINS` 声明的插件未安装 | 按日志给出的命令安装，或 `pnpm run setup -- --from-manifest` |
| 插件互相依赖无法启动 | 缺少依赖的能力契约 | 看启动摘要里的依赖解析报错；先启用被依赖的插件 |
| 停用插件被拒绝 | 存在**已启用的反向依赖** | 先停用依赖它的插件（`pnpm plugin list` 可看依赖关系） |
| 安装任务失败 | 见任务日志末尾的失败原因 | `pnpm plugin jobs <jobId>` 查看完整日志 |
| 安装参数导致失败 | 安装命令参数需**按包管理器区分**（`--no-audit` / `--no-fund` 是 npm 专有） | 现代码会自动探测包管理器拼参数；若从旧版本升级请先更新本体 |
| 插件后台页面 404 / 白屏 | 插件未启用、页面入口文件缺失、路由未注册 | 启用并**重启进程**；确认 `admin.pages[].entry` 文件存在；`pnpm validate` 会校验 |
| 装了插件但来源显示“未知” | 安装完成但内核尚未重启 | 重启进程；内核会为未登记插件补写最小记录 |
| 插件目录被跳过、不加载 | 名称以 `.` 开头，或形如 `.incoming-*` / `.backup-*` | 这些是安装器的瞬时目录，发现机制**刻意跳过**；把最终目录改成正常名 |

## 4. 主题问题

| 症状 | 可能原因 | 处理 |
| --- | --- | --- |
| 主题校验不通过 | `theme.json` 字段错（如把 `settings` 写成 `settingsSchema`）、`templates` 声明的文件缺失 | 对照 schema 与 [[主题与外观\|Themes]] 的字段表 |
| 页面白屏 / 渲染报错 | 模板里引用了未注册的路由或变量 | `url()` 对未注册路由会降级为 `#` 并告警一次；看日志中的模板错误与行号 |
| 模板没生效 | 模板查找顺序 | 顺序为：内容指定版式键 → 显式文件名 → `templates[kind]` → 主题 `fallback.njk` → Core `fallback.njk` |
| 改了 CSS/JS 没变化 | 静态资源带版本指纹 + `immutable` 缓存 | **提升 `theme.json` 的 `version`** |
| 主题设置保存报 409 | revision 乐观锁冲突（有别人先改了） | 刷新页面重新提交 |
| 切换主题后内容版式不对 | 版式键在新主题里不存在 | 会自动回退到 kind 模板；想保留效果需在新主题声明同名键 |
| 禁用插件后主题某块空白 | 主题用 `has_feature()` 包裹的区块整体不渲染 | 属于预期行为 |

## 5. 后台问题

| 症状 | 可能原因 | 处理 |
| --- | --- | --- |
| 登录后跳回登录页 | Cookie 被拦、`SITE_URL` 与访问地址不一致导致 CSRF/同源判定失败 | 核对反向代理是否正确透传 `Host` 与 `X-Forwarded-Proto` |
| 后台白屏 | 静态资源 404（未构建）、插件界面加载失败 | `pnpm --filter @ricenote/admin build`；刷新看控制台与网络面板 |
| 侧栏缺某个入口 | 对应插件未启用，或当前角色**没有该权限点** | 启用插件并重启；在「角色与权限」里核对权限 |
| 打开插件页提示「已声明但未注册」 | 插件未启用 | 启用并重启进程 |
| 改了设置但没生效 | 存在待生效变更 | 顶栏点「待重启」；确认进度轮询结束（会等 `startedAt` 变化以确认是新进程） |
| 重启后仍是旧行为 | **进程内软重启不重载模块代码** | 改了插件/内核代码必须重启**进程** |
| 操作被拒绝并提示权限不足 | 能力校验 **fail-closed** | 这是预期的安全行为；检查角色权限点 |
| 403 / CSRF 失败 | 写操作缺少 CSRF 令牌，或跨站提交 | 使用后台界面正常操作；确认 `CSRF_ENABLED` 与代理配置 |

## 6. 前台问题

| 症状 | 可能原因 | 处理 |
| --- | --- | --- |
| 首页内容不是最新的 | HTML 缓存（默认 TTL 120 秒） | 等待 TTL、后台改一次相关设置清缓存，或临时 `RENDER_CACHE_ENABLED=false` |
| 导航栏少了一项 | 该导航项目标是**未发布或已删除**的内容 | 前台刻意跳过死链；到「导航栏」页会看到失效原因 |
| 搜索没结果 | 关键词过短、索引缺失、数据源插件未启用 | 关键词过短会自动回退 `LIKE`；确认 `rice.search` 与 `rice.posts` 均已启用 |
| 中文关键词搜不到 | 索引未建立（旧数据） | 确认 `rn_posts` 的 ngram FULLTEXT 索引存在；迁移已应用 |
| 评论提交后没有显示 | 先审后发 | 到后台「评论审核」查看 `pending` 队列 |
| 表单提交被拒 | 同源校验 / 频率限制 / 蜜罐 | 正常访客一般不会触发；看日志中的反垃圾判定 |
| 图片 404 | 媒体文件缺失或路径不对 | 到媒体库确认；公开地址形如 `/media/:id` |
| 外链点了没反应 | 地址被白名单拒绝 | 只接受 `/` 开头的站内路径与 `http(s)://` 绝对地址 |

## 7. 备份与恢复

| 症状 | 处理 |
| --- | --- |
| 备份返回 `RN_BACKUP_TOOL_MISSING`（503） | 宿主机没有 `mysqldump` / `mysql`。安装 MySQL 客户端，或用 `MYSQLDUMP_BIN` / `MYSQL_BIN` 指定绝对路径 |
| 上传的备份包无法恢复 | 备份包需通过只读预览校验（Zip Slip、扩展名白名单等）；点文件（如 `.gitkeep`）会被跳过 |
| 恢复后站点异常 | 恢复会返回 `restartRequired` 并清空 HTML 缓存；重启进程后再验证 |
| 恢复前担心不可逆 | 恢复前系统会**自动生成当前状态快照**，可从快照列表回滚 |

## 8. 还是不行？

请带上这些信息再提问（能极大缩短定位时间）：

1. `GET /api/health` 的完整返回；
2. **启动摘要横幅**（版本、插件计数、失败插件名）；
3. 后台「运行日志」中对应的错误条目（含请求 ID 与时间）；
4. `pnpm validate` 的输出；
5. 你的版本号与部署方式（容器 / 裸机）。

提交地址：[github.com/ricenote/ricenote/issues](https://github.com/ricenote/ricenote/issues)
