# 常见问题

本页收集**真实踩过的坑**与容易被误读的语义约定。每条都注明原因，方便你判断自己遇到的是不是同一个问题。

---

## 安装与升级

### 我运行 `pnpm setup` 没看到安装向导，好像改了我的 shell 配置？

裸 `pnpm setup` 是 **pnpm 自带的命令**（配置 `PNPM_HOME` 与 `PATH`），它会抢在同名脚本之前执行。

✅ 正确写法：`pnpm run setup`（或 `pnpm ricenote setup`）。

### 升级宿主补丁版本后，要不要改插件声明里的宿主区间？

**不用。** 插件声明的是宿主区间，跟随宿主的次版本：宿主为 `A.B.z` 时写 `^A.B.0`（只放行同一个次版本）。

在 `0.x` 阶段，**只有次版本号跃迁**（如 `0.5.x → 0.6.0`）才会跨出区间。补丁升级仍在其范围内。

> 反过来要留意：次版本跃迁后，旧插件声明的区间会与新宿主对不上，启动期会判定不兼容 ——
> 这属于正常现象，请走插件更新流程，**不要手改插件的 `package.json`**。

升级插件请走后台或 `pnpm plugin update`，**不要手改插件的 `package.json`**。

### `pnpm theme install xxx.zip` 报「未知子命令」？

这是**过时的提示文案**：`theme` 命令只支持 `list` / `activate` / `settings`，**没有 `install`**。
（安装向导结束语里那句提示引用了不存在的命令。）

✅ 主题包安装走**后台**：外观中心 → 安装主题（`POST /api/admin/themes/install`），或把主题目录直接放进 `THEMES_DIR`。

### 迁移能回退吗？

**不能。** 迁移**只有前向演进**，没有 down 迁移；插件停用也不删表。所以升级前**必须先备份**。

另外：**不要修改已应用的迁移文件** —— 每个迁移都记录了 SHA-256 校验值，内容被改动会**拒绝启动**。演进只能新增迁移文件。

### `RICENOTE_PLUGINS` 里写了插件，启动时为什么没自动装上？

内核在启动期对声明式清单**只核对不安装**。缺件或版本不符时，日志会给出**可直接执行的安装命令**。

这是刻意的设计：启动期不应该隐式修改磁盘。需要自动装请用 `pnpm run setup -- --from-manifest`。

### 反向代理后，为什么 `HOST`/`PORT` 和 `SITE_URL` 不一样？

因为它们是两件事：

- `HOST` / `PORT` 是**本进程监听**的地址（只需保证该端口可达）；
- `SITE_URL` 是**访客访问**的对外地址（用于 canonical URL 与主题 `url()`）。

两者不一致是**正常形态**。真正需要检查的是：`SITE_URL` 不能被留在 `http://localhost:3000`，否则站点地图与绝对链接都会指向 localhost。

### `.env.example` 里的 `LOG_FORMAT` / `NO_COLOR` / `DB_ROOT_PASSWORD` 配了没效果？

要分两类看：

| 键 | 情况 |
| --- | --- |
| `LOG_FORMAT` | **生效**。它不在配置加载器的 schema 里，而是由日志模块（`packages/core/src/logger.ts`）直接读取环境变量；取值 `pretty` / `json`，留空则按 TTY 自动判断 |
| `NO_COLOR` | **生效**。同样由日志模块直接读取，设置后关闭终端着色 |
| `DB_ROOT_PASSWORD` | **不生效**：应用代码未读取它，只在 `docker-compose.yml` 中供 MySQL 容器自身使用 |

也就是说，只有 `DB_ROOT_PASSWORD` 属于文档与实现的偏差；完整配置清单见 [[环境变量参考|Configuration]]。

## 部署

### `docker compose up -d` 构建失败，提示找不到 `docker/server.Dockerfile`？

**当前仓库中没有 `docker/` 目录**，而 `docker-compose.yml` 引用了 `docker/server.Dockerfile` 与 `docker/nginx.conf`。

部署前需要自备这两个文件（要点见 [[容器化部署与反向代理|Deployment]] 的「需要自备的文件」），
或者不用容器：`pnpm build && pnpm start` 配合宿主机 systemd + nginx。

### 容器重建后，在线安装的插件和上传的图片还在吗？

**在**。`./storage`、`./plugins`、`./themes` 都是宿主目录挂载进容器的，因此插件、主题、上传文件都不随容器重建丢失。数据库在 Docker 卷 `mysql-data` 里。

## 主题与外观

### 改了主题的 CSS，访客还是看到旧样式？

主题静态资源地址带**主题版本指纹**并返回 `immutable` 长缓存：

```
/theme-assets/rice.default/css/style.css?v=1.1.0
```

✅ **改了主题资源就提升 `theme.json` 的 `version`**，否则浏览器会一直用旧文件。

### 我在 `theme.json` 里写 `settingsSchema` 报校验失败？

主题的设置字段名是 **`settings`**；`settingsSchema` 是**插件** manifest 的字段名。

`theme.schema.json` 设了 `additionalProperties: false`，写错字段名会直接被拒绝。

### 主题里 `site.logoUrl` 判断为什么和文档写的不一样？

代码只在值为真时才放入该键，因此**未设置时该键不存在（`undefined`），不是空字符串**。

模板里请写 `{% if site.logoUrl %}`，不要写 `{% if site.logoUrl == '' %}`。

### 内容选了某个版式，换主题后会不会出问题？

不会。内容只保存**版式键**（如 `narrow`），渲染时若当前主题没有该键或文件缺失，会**优雅回退到 kind 模板**，不会报错。

### 主题模板里为什么没有 `absoluteUrl()`？

模板里可用的是 `site_url('/path')`。`absoluteUrl` 是 SDK 内部函数，不是模板 helper。

## 内容与后台

### 仪表盘的某些统计一直是 0？

统计依赖于**提供该能力的插件**。插件未启用时，对应统计降级为 0 并出现在 `missingServices` 里，页面顶部会给出告警。

这是“插件可独立启停”的正常表现，不是故障。

### 停用插件会不会丢数据？

**不会。** 插件停用不 drop 表；重新启用后数据仍在。真正会删数据的只有显式的删除操作与备份恢复。

### 忘记管理员密码了怎么办？

1. 若有**其他管理员**账号：在「用户」页重置你的密码。
2. 若只有一个管理员：直接改数据库，或删除该用户后重跑 `pnpm run setup` 重建（首次启动会按 `BOOTSTRAP_ADMIN_*` 创建）。

> 管理员**不能重置自己的密码**（这是刻意的：本人改密必须走 `/me/password` 并校验原密码），重置他人密码后该用户全部会话失效。

### 保存文章时标签重名导致失败？

服务端按 slug 判重返回 409，前端会**自动回退**为"重新拉取词条列表并选中已存在的那条"并提示已选中。

若你仍在旧版本上遇到保存失败，升级到 0.5.1 及以上即可。

### 硬刷新编辑页会变成“新建一篇重复文章”？

这是 0.5.1 **已修复**的缺陷：后台守卫的兜底路由重新解析时，把 `path` 写成了对象形式，导致带 `?id=` 的查询参数被剥掉，于是“编辑文章”变成“新建”。

若你在旧版本遇到：**应用内点击跳转不受影响**，只有硬刷新/直接粘贴深链会触发。升级即可。

### 后台页面出现「插件已声明但未注册」的提示？

说明该插件声明了这个后台页面，但**当前未启用**（或尚未重启生效）。启用插件并重启进程后即可访问。

## 插件开发

### 贡献的后台组件读不到 `context`，点了没反应也不报错？

Vue 只会把组件**自己声明过**的字段填进 `setup(props)`，未声明的会落到 `ctx.attrs`，于是 `setup(props)` 静默拿到 `undefined`。

✅ 用 `defineAdminContribution()` 时**必须声明 `props`**。详见 [[插件自带后台界面|Plugin-API-Admin-UI]]。

### `replaceable: false` 为什么拦住了我自己？

`replaceable: false` **只约束第三方**：提供方自己的 `replace` 不受约束。

判据是三段条件：`mode === 'replace' && !replaceable && consumer !== provider`。

### 插件禁用后，它的表还在吗？重新启用会不会重复建表？

表在（停用不 drop）。迁移有校验值防线，重复执行是**幂等**的（会显示“跳过 M 项”）。

### 开发时改了插件代码，为什么没生效？

进程内软重启**不会重载模块代码**（Node ESM 缓存按 URL 生效）。

- 改**配置**或**启停插件**：后台重启按钮即可；
- 改**插件/内核代码**：必须重启**进程**。

> 例外：登记在 `RICENOTE_LOCAL_PLUGINS` 的目录在开发环境会被监视并**自动重启内核**。

### 安装插件时提示“拒绝安装”？

两种常见原因：

1. 该插件把宿主提供的包（`@ricenote/plugin-sdk` 等）**写成了普通依赖** —— 会导致两份实例，因此被拒绝。
2. 目标目录被**其他插件 ID** 占用 —— 防止互相覆盖。
